### Added
- **Core RAG Architecture**: Hybrid candidate retrieval combining dense sentence embeddings (`all-MiniLM-L6-v2`) and sparse keyword retrieval (BM25) via Reciprocal Rank Fusion (RRF).
- **Advanced Query Transformations**: Multi-query decomposition, semantic expansion, and Hypothetical Document Embeddings (HyDE) with query routing heuristics.
- **Precision Reranking**: Cross-encoder scoring (`cross-encoder/ms-marco-MiniLM-L-6-v2`) with graceful fallback to dense similarity.
- **Multi-Tenant Document Workspace**: User-scoped document uploads, sha256 deduplication, background asynchronous chunking, and isolated ChromaDB vector indexing.
- **Research Answer Publication**: Clickable, verifiable citation linking (`[S1]`, `[S2]`) with passage preview panel and source document traceability.
- **Performance Engineering & Bounded Caching**: In-memory LRU embedding cache and cryptographic retrieval candidate cache with multi-tenant namespace isolation.
- **Asynchronous Execution Model**: Bounded LLM generator semaphore (`max_concurrent_llm_requests=8`), subquery parallel retrieval, and background ingestion rate limiting.
- **Centralized Production Settings**: Pydantic Settings integration with `SecretStr` masking, production invariant validation, and decoupled environment configuration.
- **Deployment Health Probes**: Decoupled process liveness (`GET /health/live`) and dependency readiness (`GET /health/ready`) with bounded 3.0s ChromaDB timeouts and fail-fast lifespan initialization.
- **Automated Delivery Pipeline**: GitHub Actions CI with Ruff linting, disposable Alembic migration testing, Vite production bundle build, and deployment smoke tests.

### Changed
- Replaced monolithic script execution with modular FastAPI service architecture and React 19 single-page application.
- Decoupled database schema migrations into explicit pre-deployment operations (`alembic upgrade head`).

### Fixed
- Prevented cross-tenant cache key leakage by embedding user IDs and document corpus version hashes into retrieval cache keys.
- Enforced thread-local SQLAlchemy session boundaries to eliminate cross-task session pollution during concurrent chat requests.
- Prevented process hangs on unhealthy vector stores through bounded executor timeouts.

### Security
- Protected `LLM_API_KEY` and `JWT_SECRET_KEY` with Pydantic `SecretStr` masking in string representations, JSON serializations, and tracebacks.
- Verified repository `.gitignore` hygiene excluding secrets (`.env*`), SQLite databases (`*.db`), and uploaded PDF files.
- Restricted CI permissions to `contents: read`.

### Known Limitations
- Single-instance local SQLite and local storage configurations require durable object storage (`STORAGE_TYPE=s3`) for multi-worker production clusters.
- File upload payload capped at 20MB by default (`MAX_UPLOAD_SIZE_MB=20`).
